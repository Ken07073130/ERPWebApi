# ERP/MES 后端架构与目录结构规范

> 技术栈：ASP.NET Core 8 Web API · EF Core 8（SqlServer）· JWT
> 前端：Vue 3 + Element Plus（独立仓库，通过 HTTP + CORS 交互）
> 适用范围：内部 ERP / MES 生产管理系统

---

## 一、总体决策：多项目解决方案

整洁架构的核心是**依赖规则**（Dependency Rule）：源码依赖只能从外层指向内层。这个约束**只有用独立的项目（.csproj）才能真正强制**——同项目内靠文件夹区分，任何人不小心 `using` 一下就穿透了，编译器不会拦。

因此推荐把现在的单项目 `ERPWebApi` 拆成一个解决方案 + 4 个类库 + 3 个测试项目。

> **例外情况**：如果团队只有 1~2 人、且明确只做单一后端服务，用「单项目 + 文件夹分层」也能跑，只是依赖规则退化为口头约定。本文档给的是多项目版本，单项目版本见第五节。

### 解决方案整体结构

```
ERP.sln
│
├── src/
│   ├── ERP.Domain/                 # ① 领域层    —— 零外部依赖，业务规则核心
│   ├── ERP.Application/            # ② 应用层    —— 用例编排，依赖 Domain
│   ├── ERP.Infrastructure/         # ③ 基础设施层 —— 数据/外部系统，依赖 Application
│   └── ERP.Api/                    # ④ 表现层    —— HTTP 入口，依赖 Application + Infrastructure
│
├── tests/
│   ├── ERP.Domain.UnitTests/       # 领域逻辑单测（最快、最该多写）
│   ├── ERP.Application.UnitTests/  # 用例/Handler 单测
│   └── ERP.Api.IntegrationTests/   # 端到端 API 测试（WebApplicationFactory + Testcontainers）
│
├── docs/
├── Directory.Build.props           # 全解决方案统一编译属性
├── Directory.Packages.props        # 中央包版本管理（CPM）
├── .editorconfig
├── .gitignore
└── README.md
```

### 项目引用关系（唯一正确的方向）

| 项目 | 允许引用 | 说明 |
|---|---|---|
| `ERP.Domain` | **无** | 连 EF Core 都不能引 |
| `ERP.Application` | `ERP.Domain` | 依赖抽象，不依赖实现 |
| `ERP.Infrastructure` | `ERP.Application` | 实现 Domain/Application 中定义的接口 |
| `ERP.Api` | `ERP.Application` + `ERP.Infrastructure` | 只为了在启动时注册 DI，业务代码里不出现 Infrastructure 类型 |
| `tests/*` | 被测项目 | — |

> **关于 Api 引用 Infrastructure**：严格派主张 Api 完全不引用 Infrastructure，改成 `Infrastructure` 暴露 `AddInfrastructure()` 扩展方法、由 Api 调用。但扩展方法本身也要被引用才能调用，所以**完全解耦做不到**——只要保证 `Api` 的 `Controllers/` 里不 `using ERP.Infrastructure` 即可。这是务实做法，也是主流模板（如 Jason Taylor 的 Clean Architecture 模板）的选择。

## 二、逐层目录结构与职责

### ① ERP.Domain —— 领域层

**职责**：承载业务规则本身。这里不应该出现任何"技术"概念——没有 HTTP、没有数据库、没有 JSON、没有 EF Core。所有代码都是纯粹的 C# 对象与逻辑。

```
ERP.Domain/
├── Common/
│   ├── BaseEntity.cs               # 实体基类：Id / 创建时间 / 创建人 / 行版本
│   ├── AuditableEntity.cs          # 带审计字段的抽象基类
│   ├── ValueObject.cs              # 值对象基类（重写相等性比较）
│   ├── IAggregateRoot.cs           # 聚合根标记接口（仓储只针对聚合根）
│   ├── IDomainEvent.cs             # 领域事件标记接口
│   └── DomainException.cs          # 业务规则被违反时抛出（区别于系统异常）
│
├── Entities/                       # 领域实体，按业务模块分子目录
│   ├── Identity/                   # User, Role, Permission, UserRole
│   ├── Production/                 # WorkOrder, WorkOrderItem, Routing, WorkCenter
│   ├── Inventory/                  # Material, Warehouse, StockEntry, InventoryTransaction
│   ├── Sales/                      # SalesOrder, SalesOrderLine, Customer
│   ├── Purchase/                   # PurchaseOrder, PurchaseOrderLine, Supplier
│   ├── Quality/                    # InspectionOrder, InspectionItem, QualityStandard
│   └── Equipment/                  # Equipment, MaintenancePlan, MaintenanceRecord
│
├── ValueObjects/                   # 无标识、不可变、用值相等
│   ├── Address.cs                  # 地址
│   ├── Money.cs                    # 金额（含币种，避免用 decimal 裸奔）
│   ├── Quantity.cs                 # 数量 + 计量单位
│   ├── BatchNumber.cs              # 批次号（MES 高频）
│   └── DateRange.cs                # 时间区间
│
├── Enums/                          # 领域枚举
│   ├── WorkOrderStatus.cs          # 草稿/已下达/生产中/已完工/已关闭
│   ├── InspectionResult.cs         # 合格/不合格/让步接收
│   └── ...
│
├── Events/                         # 领域事件（过去式命名）
│   ├── WorkOrderCreatedEvent.cs
│   └── WorkOrderCompletedEvent.cs
│
├── Interfaces/                     # ★ 仓储接口定义在此层（依赖倒置的关键）
│   ├── IRepository.cs              # 泛型仓储：IRepository<T>
│   ├── IUnitOfWork.cs              # 工作单元
│   ├── IWorkOrderRepository.cs     # 特定聚合的仓储（有专属查询方法时才需要）
│   └── ICurrentUserService.cs      # 只读暴露当前用户信息给领域逻辑用
│
├── Specifications/                 # 规约模式（可选，配合 Ardalis.Specification）
│   └── WorkOrders/ActiveWorkOrderSpec.cs
│
└── Constants/                      # 领域常量
    └── Permissions.cs              # 权限点字符串常量（前后端共用命名）
```

**关键约定**：
- **仓储接口放 Domain，实现放 Infrastructure**——这是整洁架构里最容易被搞反的一点。
- 领域实体**禁止**有 `public` 无参构造函数 + 全公开 setter（那是"贫血模型"），应该用工厂方法或构造函数保证不变量：
  ```csharp
  public class WorkOrder : AuditableEntity, IAggregateRoot
  {
      private readonly List<WorkOrderItem> _items = new();
      public IReadOnlyCollection<WorkOrderItem> Items => _items.AsReadOnly();
      public WorkOrderStatus Status { get; private set; }

      // 构造函数保证：不允许创建违反规则的工单
      public WorkOrder(string orderNo, int quantity)
      {
          if (quantity <= 0) throw new DomainException("工单数量必须大于 0");
          OrderNo = orderNo;
          Status = WorkOrderStatus.Draft;
      }

      // 业务行为通过方法暴露，而不是让外部直接改 Status
      public void Release()
      {
          if (Status != WorkOrderStatus.Draft)
              throw new DomainException("只有草稿状态可以下达");
          Status = WorkOrderStatus.Released;
          AddDomainEvent(new WorkOrderReleasedEvent(Id));
      }
  }
  ```

### ② ERP.Application —— 应用层

**职责**：编排用例（Use Case）。它**只依赖 Domain**，通过 Domain 定义的接口操作数据。这一层决定"做什么"，不决定"怎么存"。**这里没有 EF Core**。

```
ERP.Application/
├── Common/
│   ├── Behaviors/                  # MediatR 管道行为（横切关注点）
│   │   ├── ValidationBehavior.cs   #   统一跑 FluentValidation
│   │   ├── LoggingBehavior.cs      #   统一记录请求/耗时
│   │   ├── TransactionBehavior.cs  #   命令自动包事务
│   │   └── PerformanceBehavior.cs  #   慢请求告警
│   ├── Exceptions/
│   │   ├── ValidationException.cs  # 参数校验失败 → 映射到 400
│   │   ├── NotFoundException.cs    # 实体不存在     → 映射到 404
│   │   └── ForbiddenAccessException.cs  # → 映射到 403
│   ├── Interfaces/                 # ★ 应用层需要、由 Infrastructure 实现
│   │   ├── IApplicationDbContext.cs # 暴露 DbSet，供 Handler 直接查询
│   │   ├── IDateTime.cs            # 可测试的时钟（别直接 DateTime.Now）
│   │   ├── IJwtTokenService.cs     # 签发 Token
│   │   ├── IFileStorage.cs         # 文件/图纸上传
│   │   ├── ICacheService.cs        # 缓存抽象
│   │   └── IEmailSender.cs         # 通知
│   ├── Models/
│   │   ├── Result.cs               # 统一返回值 Result<T>
│   │   ├── PaginatedList<T>.cs     # 分页结果
│   │   └── LookupDto.cs            # 下拉框通用 DTO
│   └── Mappings/
│       └── MappingProfile.cs       # AutoMapper / Mapster 映射配置
│
├── Features/                       # ★ 按业务功能垂直切分（CQRS）
│   ├── WorkOrders/
│   │   ├── Commands/               # 写操作
│   │   │   ├── CreateWorkOrder/
│   │   │   │   ├── CreateWorkOrderCommand.cs
│   │   │   │   ├── CreateWorkOrderCommandHandler.cs
│   │   │   │   └── CreateWorkOrderCommandValidator.cs
│   │   │   ├── ReleaseWorkOrder/
│   │   │   └── CompleteWorkOrder/
│   │   ├── Queries/                # 读操作
│   │   │   ├── GetWorkOrderList/
│   │   │   │   ├── GetWorkOrderListQuery.cs
│   │   │   │   ├── GetWorkOrderListQueryHandler.cs
│   │   │   │   └── WorkOrderListVm.cs
│   │   │   └── GetWorkOrderDetail/
│   │   └── EventHandlers/          # 领域事件处理器
│   │       └── WorkOrderCompletedEventHandler.cs
│   ├── Inventory/
│   ├── Sales/
│   ├── Quality/
│   └── Identity/
│
├── DTOs/                           # 跨 Feature 复用的数据传输对象
│   ├── WorkOrders/
│   │   ├── WorkOrderDto.cs
│   │   └── CreateWorkOrderRequest.cs
│   └── Common/
│
├── Validators/                     # 跨 Feature 复用的校验器
│
└── DependencyInjection.cs          # ★ AddApplication() 扩展方法
```

**为什么用 `Features/` 而不是 `Services/`**：
ERP 这类系统模块多（工单、库存、质检、设备……），如果按 `Controllers/ Services/ Repositories/` 横向分层，改一个"工单下达"功能要同时翻 5 个文件夹；按 Feature 纵向切分后，一个功能的全部代码在同一目录下，新人上手和代码评审都容易得多。

**如果团队不熟悉 CQRS**：把 `Features/` 换成 `Services/` 即可，一个模块一个 `WorkOrderService.cs` 类，方法对应用例。**但 DTO 与实体的分离、`Common/Interfaces/` 的位置不变**——这部分是整洁架构的骨架，不能省。

### ③ ERP.Infrastructure —— 基础设施层

**职责**：所有"技术实现细节"。数据库、缓存、消息队列、文件系统、第三方 API、JWT 签发。**Domain 和 Application 定义的接口，在这里落地成具体类。**

```
ERP.Infrastructure/

│   ├── Contexts/

│   │   └── ApplicationDbContextFactory.cs # 设计时工厂（供 dotnet ef 用）
│   ├── Configurations/                    # IEntityTypeConfiguration<T>，一实体一文件
│   │   ├── WorkOrderConfiguration.cs      #   索引、长度、关系、表名
│   │   ├── InventoryTransactionConfiguration.cs
│   │   └── ...
│   ├── Repositories/
│   │   ├── EfRepository.cs                # 泛型仓储实现 IRepository<T>
│   │   ├── UnitOfWork.cs                  # IUnitOfWork 实现
│   │   └── WorkOrderRepository.cs         # 聚合专属仓储实现
│   ├── Interceptors/
│   │   ├── AuditableEntityInterceptor.cs  # 保存时自动填创建人/修改人/时间
│   │   └── DispatchDomainEventsInterceptor.cs # 保存后自动派发领域事件
│   ├── Migrations/                        # ★ EF Core 迁移脚本（必须提交到 Git）
│   ├── Converters/                        # 值对象 ↔ 数据库类型的转换器
│   │   └── ValueObjectConverter.cs
│   └── Seed/
│       └── ApplicationDbContextInitializer.cs # 首次启动：迁移 + 种子数据

├── Identity/
│   ├── JwtTokenService.cs                 # 签发/刷新 JWT
│   ├── PasswordHasher.cs                  # 密码哈希（PBKDF2 / BCrypt）
│   └── CurrentUserService.cs              # 从 HttpContext 读当前用户
│
├── Services/
│   ├── DateTimeService.cs                 # IDateTime 实现
│   ├── LocalFileStorage.cs                # IFileStorage 实现（生产可换 OSS/MinIO）
│   ├── RedisCacheService.cs               # ICacheService 实现（可选）
│   └── SmtpEmailSender.cs                 # IEmailSender 实现（可选）
│
├── ExternalServices/                      # 与外部系统对接
│   ├── MesApiClient.cs                    # MES 接口客户端
│   ├── ErpGatewayClient.cs                # 上游 ERP 网关
│   └── Handlers/                          # 统一重试/超时/鉴权 DelegatingHandler
│
├── Options/                               # 强类型配置类（绑定 appsettings 节点）
│   ├── JwtSettings.cs
│   ├── ConnectionStringsOptions.cs
│   └── FileStorageOptions.cs
│
└── DependencyInjection.cs                 # ★ AddInfrastructure(configuration) 扩展方法
```

**注意**：`Migrations/` 目录**必须提交到版本库**。它是数据库结构的唯一事实来源，靠"生产环境自动迁移"或"人工执行 SQL"都会出事。

### ④ ERP.Api —— 表现层

**职责**：只做三件事——接收 HTTP 请求、把请求交给 Application 层、把结果转成 HTTP 响应。**这一层不允许出现业务逻辑**。

```
ERP.Api/
├── Controllers/                    # 按模块命名
│   ├── ApiControllerBase.cs        # 基类，收敛公共返回逻辑
│   ├── WorkOrdersController.cs
│   ├── InventoryController.cs
│   ├── AuthController.cs           # 登录/刷新 Token（唯一允许直接做点事的地方）
│   └── ...
│
├── Middleware/
│   ├── ExceptionHandlingMiddleware.cs # ★ 全局异常 → ProblemDetails
│   └── RequestLoggingMiddleware.cs
│
├── Filters/
│   └── ApiExceptionFilterAttribute.cs
│
├── Extensions/
│   ├── ServiceCollectionExtensions.cs # AddApiServices()
│   ├── SwaggerExtensions.cs           # Swagger + JWT Bearer 安全定义
│   └── WebApplicationExtensions.cs    # 迁移+种子数据、健康检查映射
│
├── Configuration/
│   └── (可选) 配置加载扩展
│
├── wwwroot/                        # 静态资源（若需托管前端产物）
├── Properties/launchSettings.json
├── appsettings.json                # 不含密钥
├── appsettings.Development.json    # 本地连接串（Git 忽略或只放占位）
├── Program.cs                      # ★ 组合根（Composition Root）
└── ERP.Api.csproj
```

**Controller 应该长这样**（薄到极致）：

```csharp
[ApiController]
[Route("api/[controller]")]
[Authorize]
public class WorkOrdersController : ApiControllerBase
{
    private readonly ISender _mediator;

    public WorkOrdersController(ISender mediator) => _mediator = mediator;

    [HttpGet]
    [ProducesResponseType(typeof(PaginatedList<WorkOrderListVm>), StatusCodes.Status200OK)]
    public async Task<ActionResult<PaginatedList<WorkOrderListVm>>> GetList(
        [FromQuery] GetWorkOrderListQuery query, CancellationToken ct)
        => Ok(await _mediator.Send(query, ct));   // 没有 if/else，没有业务判断

    [HttpPost]
    [Authorize(Policy = Permissions.WorkOrder.Create)]
    public async Task<ActionResult<Guid>> Create(CreateWorkOrderCommand command, CancellationToken ct)
        => Ok(await _mediator.Send(command, ct));
}
```

**不放 CORS 白名单硬编码**——Vue 3 开发服务器（Vite 默认 `http://localhost:5173`）的地址写进配置，见第六节。

## 三、横切配置文件

### Directory.Build.props（放在 `src/` 上层，全解决方案生效）

避免每个 csproj 重复写相同的属性：

```xml
<Project>
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <LangVersion>12.0</LangVersion>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>
    <GenerateDocumentationFile>false</GenerateDocumentationFile>
  </PropertyGroup>
</Project>
```

### Directory.Packages.props（中央包版本管理）

所有包版本集中在一处，各项目引用时不写 Version。ERP 项目模块多，这个能救命：

```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>
  <ItemGroup>
    <!-- EF Core：四个包版本必须完全一致 -->
    <PackageVersion Include="Microsoft.EntityFrameworkCore" Version="8.0.31" />
    <PackageVersion Include="Microsoft.EntityFrameworkCore.SqlServer" Version="8.0.31" />
    <PackageVersion Include="Microsoft.EntityFrameworkCore.Design" Version="8.0.31" />
    <PackageVersion Include="Microsoft.EntityFrameworkCore.Tools" Version="8.0.31" />

    <PackageVersion Include="Microsoft.AspNetCore.Authentication.JwtBearer" Version="8.0.31" />

    <!-- 应用层 -->
    <PackageVersion Include="MediatR" Version="12.4.1" />
    <PackageVersion Include="FluentValidation.DependencyInjectionExtensions" Version="11.11.0" />
    <PackageVersion Include="AutoMapper" Version="13.0.1" />

    <!-- 表现层 -->
    <PackageVersion Include="Swashbuckle.AspNetCore" Version="6.6.2" />
    <PackageVersion Include="Serilog.AspNetCore" Version="8.0.3" />
  </ItemGroup>
</Project>
```

> ⚠️ **MediatR 授权注意**：MediatR **12.x 及以前是 Apache 2.0 免费**；**13.0 起改为商业授权**（LuckyPennySoftware），企业内部系统商用也需要买 License。上面的 12.4.1 无此问题，升级前请先确认授权政策。替代方案：Wolverine、或直接用 `IWorkOrderService` 这种手写应用服务。

## 四、Program.cs 组合根

```csharp
using ERP.Api.Extensions;
using ERP.Application;
using ERP.Infrastructure;
using Serilog;

var builder = WebApplication.CreateBuilder(args);

// ── 0. 日志：先接管，保证启动期异常也能落盘 ────────────────────────
builder.Host.UseSerilog((context, cfg) => cfg
    .ReadFrom.Configuration(context.Configuration)
    .Enrich.FromLogContext()
    .WriteTo.Console()
    .WriteTo.File("logs/log-.txt", rollingInterval: RollingInterval.Day));

// ── 1. 分层注册：每层自己管自己的实现，组合根只负责调用 ──────────────
builder.Services
    .AddApplication()                                // MediatR + FluentValidation + AutoMapper
    .AddInfrastructure(builder.Configuration)        // DbContext + 仓储 + JWT 签发 + 外部服务
    .AddApiServices(builder.Configuration);          // JWT 认证 + CORS + Swagger + 健康检查

var app = builder.Build();

// ── 2. 开发环境：Swagger + 自动迁移/种子数据 ────────────────────────
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI(c => c.SwaggerEndpoint("/swagger/v1/swagger.json", "ERP API v1"));
    await app.Services.InitialiseDatabaseAsync();    // 生产环境改为发布流程中执行迁移
}

// ── 3. 中间件顺序很关键，不要随意调换 ───────────────────────────────
app.UseMiddleware<ExceptionHandlingMiddleware>();    // 最外层，兜住所有异常
app.UseSerilogRequestLogging();
app.UseHttpsRedirection();
app.UseCors(CorsPolicies.VueFrontend);               // 必须在 UseAuthentication 之前
app.UseAuthentication();                             // 先认证
app.UseAuthorization();                              // 再授权
app.MapControllers();
app.MapHealthChecks("/health");

app.Run();
```

## 五、各层 DI 注册扩展方法

### Application 层：`ERP.Application/DependencyInjection.cs`

```csharp
using System.Reflection;
using ERP.Application.Common.Behaviors;
using FluentValidation;
using Microsoft.Extensions.DependencyInjection;

namespace ERP.Application;

public static class DependencyInjection
{
    public static IServiceCollection AddApplication(this IServiceCollection services)
    {
        var assembly = Assembly.GetExecutingAssembly();

        services.AddMediatR(cfg =>
        {
            cfg.RegisterServicesFromAssembly(assembly);

            // 管道行为执行顺序 = 注册顺序，不能颠倒：
            // 日志 → 校验 → 事务 → 业务处理
            cfg.AddOpenBehavior(typeof(LoggingBehavior<,>));
            cfg.AddOpenBehavior(typeof(ValidationBehavior<,>));
            cfg.AddOpenBehavior(typeof(TransactionBehavior<,>));
        });

        services.AddValidatorsFromAssembly(assembly, includeInternalTypes: true);
        services.AddAutoMapper(assembly);

        return services;
    }
}
```

> 注：以上是 **MediatR 12.x** 的 API。若升级到 13.x，`RegisterServicesFromAssembly` 已更名为 `RegisterServicesFromAssemblies` 且需要传入 `Assembly[]`。

### Infrastructure 层：`ERP.Infrastructure/DependencyInjection.cs`

```csharp
using ERP.Application.Common.Interfaces;
using ERP.Domain.Interfaces;
using ERP.Infrastructure.Identity;
using ERP.Infrastructure.Persistence.Contexts;
using ERP.Infrastructure.Persistence.Interceptors;
using ERP.Infrastructure.Persistence.Repositories;
using ERP.Infrastructure.Services;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace ERP.Infrastructure;

public static class DependencyInjection
{
    public static IServiceCollection AddInfrastructure(
        this IServiceCollection services, IConfiguration configuration)
    {
        // ── 1. 数据库 ────────────────────────────────────────────────
        var connectionString = configuration.GetConnectionString("Default")
            ?? throw new InvalidOperationException(
                "缺少连接字符串 ConnectionStrings:Default，请检查 appsettings.json");

        services.AddScoped<AuditableEntityInterceptor>();
        services.AddScoped<DispatchDomainEventsInterceptor>();

        services.AddDbContext<ApplicationDbContext>((sp, options) =>
        {
            options.UseSqlServer(connectionString, sql =>
            {
                // 迁移脚本所在程序集（Infrastructure），不是 Api
                sql.MigrationsAssembly(typeof(ApplicationDbContext).Assembly.FullName);
                sql.EnableRetryOnFailure(
                    maxRetryCount: 3,
                    maxRetryDelay: TimeSpan.FromSeconds(5),
                    errorNumbersToAdd: null);   // 云数据库连接抖动必备
                sql.CommandTimeout(60);
            });

            options.AddInterceptors(
                sp.GetRequiredService<AuditableEntityInterceptor>(),
                sp.GetRequiredService<DispatchDomainEventsInterceptor>());
        });

        // ── 2. 仓储与工作单元 ─────────────────────────────────────────
        services.AddScoped<IApplicationDbContext>(sp =>
            sp.GetRequiredService<ApplicationDbContext>());
        services.AddScoped(typeof(IRepository<>), typeof(EfRepository<>));
        services.AddScoped<IUnitOfWork, UnitOfWork>();

        // ── 3. 技术能力实现 ───────────────────────────────────────────
        services.AddScoped<IJwtTokenService, JwtTokenService>();
        services.AddScoped<ICurrentUserService, CurrentUserService>();
        services.AddSingleton<IDateTime, DateTimeService>();
        services.AddScoped<IFileStorage, LocalFileStorage>();
        services.AddScoped<ICacheService, MemoryCacheService>();

        services.Configure<JwtSettings>(configuration.GetSection(JwtSettings.SectionName));

        return services;
    }
}
```

> `AddDbContext` 默认注册的生命周期就是 **Scoped**，不需要额外指定。
> 若要换成 `AddDbContextPool`（高并发场景），注意 **不能** 同时注册 `AuditableEntityInterceptor` 这类有状态拦截器。

### Api 层：`ERP.Api/Extensions/ServiceCollectionExtensions.cs`

```csharp
using System.Text;
using ERP.Api.Middleware;
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.Tokens;
using Microsoft.OpenApi.Models;

namespace ERP.Api.Extensions;

public static class CorsPolicies
{
    public const string VueFrontend = "VueFrontend";
}

public static class ServiceCollectionExtensions
{
    public static IServiceCollection AddApiServices(
        this IServiceCollection services, IConfiguration configuration)
    {
        // ── 1. 控制器 + 统一错误响应 ──────────────────────────────────
        services.AddControllers();
        services.AddProblemDetails();

        // ── 2. JWT 认证 ───────────────────────────────────────────────
        var jwtSection = configuration.GetSection("Jwt");
        var key = jwtSection["Key"]
            ?? throw new InvalidOperationException("缺少配置 Jwt:Key");

        services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
            .AddJwtBearer(options =>
            {
                options.TokenValidationParameters = new TokenValidationParameters
                {
                    ValidateIssuer           = true,
                    ValidateAudience         = true,
                    ValidateLifetime         = true,      // ★ 千万别关
                    ValidateIssuerSigningKey = true,
                    ValidIssuer              = jwtSection["Issuer"],
                    ValidAudience            = jwtSection["Audience"],
                    IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(key)),
                    ClockSkew = TimeSpan.FromSeconds(30)  // 默认 5 分钟，对内部系统太长
                };
            });

        services.AddAuthorization();

        // ── 3. CORS：给 Vue 3 开发服务器放行 ──────────────────────────
        var allowedOrigins = configuration.GetSection("Cors:AllowedOrigins").Get<string[]>()
                             ?? Array.Empty<string>();

        services.AddCors(options => options.AddPolicy(CorsPolicies.VueFrontend, policy =>
            policy.WithOrigins(allowedOrigins)   // Vite 默认 http://localhost:5173
                  .AllowAnyHeader()
                  .AllowAnyMethod()
                  .AllowCredentials()));         // 带 Cookie/Authorization 时必须

        // ── 4. Swagger，带 Bearer 按钮 ────────────────────────────────
        services.AddEndpointsApiExplorer();
        services.AddSwaggerGen(c =>
        {
            c.SwaggerDoc("v1", new OpenApiInfo { Title = "ERP/MES API", Version = "v1" });
            c.AddSecurityDefinition("Bearer", new OpenApiSecurityScheme
            {
                Name = "Authorization",
                Type = SecuritySchemeType.Http,
                Scheme = "bearer",
                BearerFormat = "JWT",
                In = ParameterLocation.Header,
                Description = "直接填 Token，不用加 Bearer 前缀"
            });
            c.AddSecurityRequirement(new OpenApiSecurityRequirement
            {
                {
                    new OpenApiSecurityScheme
                    {
                        Reference = new OpenApiReference
                        { Type = ReferenceType.SecurityScheme, Id = "Bearer" }
                    },
                    Array.Empty<string>()
                }
            });
        });

        // ── 5. 健康检查 ───────────────────────────────────────────────
        services.AddHealthChecks();

        return services;
    }
}
```

```jsonc
{
  "ConnectionStrings": {
    "Default": "Server=localhost;Database=ErpDb;User Id=sa;Password=***;TrustServerCertificate=True;"
  },
  "Jwt": {
    "Key": "至少 32 字符的对称密钥，放 User Secrets 或环境变量，不要提交到 Git",

    "Audience": "ERP.Vue",

  }

```

> ⚠️ `TrustServerCertificate=True` 不是可选项：`Microsoft.Data.SqlClient` 5.x 起**默认 `Encrypt=True`**，本地 SQL Server 用的是自签名证书，不加这个参数会直接报「证书链不受信任」。生产环境应该导入真实证书，而不是一路 `TrustServerCertificate`。

## 六、落地到当前仓库的迁移步骤

当前仓库 `ERPWebApi` 是单项目模板，改造顺序建议：

```bash
# 1. 在解决方案同级建目录骨架
mkdir src tests docs

# 2. 创建四个项目（Domain 用普通类库，Api 用 web 模板）
dotnet new classlib -n ERP.Domain       -o src/ERP.Domain
dotnet new classlib -n ERP.Application  -o src/ERP.Application
dotnet new classlib -n ERP.Infrastructure -o src/ERP.Infrastructure
dotnet new webapi  -n ERP.Api           -o src/ERP.Api --use-controllers

# 3. 把现有 ERPWebApi 的内容迁过去
#    Program.cs / appsettings*.json / Properties  →  src/ERP.Api/
#    Controllers/                                  →  src/ERP.Api/Controllers/
#    WeatherForecast.cs 及对应 Controller          →  直接删除（模板示例）

# 4. 建立引用关系
dotnet add src/ERP.Application/ERP.Application.csproj      reference src/ERP.Domain
dotnet add src/ERP.Infrastructure/ERP.Infrastructure.csproj reference src/ERP.Application
dotnet add src/ERP.Api/ERP.Api.csproj                      reference src/ERP.Application src/ERP.Infrastructure

# 5. 加入解决方案
dotnet sln add src/**/*.csproj

# 6. 编译验证
dotnet build
```

### 三个环境注意事项

1. **本机只有 .NET SDK 10.0.301，没有 .NET 8 SDK。** 目前编译 net8.0 是正常的（运行时装了 8.0.28），但如果加 `global.json` 并 pin `"version": "8.0.100"`，构建会直接失败。要么先装 .NET 8 SDK，要么写成允许前滚：
   ```json

   ```

## 七、一页速查：什么代码该放哪层

| 你想写的代码 | 该放哪层 | 不该放哪层 |
|---|---|---|
| "工单数量必须大于 0" | Domain 实体的构造函数 | ❌ Controller、❌ Validator（校验器只做格式校验） |
| 数据库连接字符串 | Api 的 appsettings | ❌ Domain、❌ Application |
| `_context.WorkOrders.Where(...)` | Application 的 QueryHandler | ❌ Controller |
| `DbSet<WorkOrder>` 的 `OnModelCreating` | Infrastructure | ❌ Application |
| HTTP 状态码 404 / 400 的映射 | Api 的 ExceptionHandlingMiddleware | ❌ Handler |
| JWT 签名逻辑 | Infrastructure | ❌ Api 的 Controller |
| "下单后自动扣减库存" | Application 的 EventHandler 或 Domain 领域服务 | ❌ Controller |
| DTO ↔ 实体 的映射 | Application 的 Mappings | ❌ Controller |
| 分页参数解析 | Application 的 Query 对象 | ❌ Controller |
| 日志埋点 | Serilog + MediatR 管道行为 | ❌ 每个方法里手写 |

---

**核心心法**：判断某段代码归属时，问一句「**如果明天把数据库换成 PostgreSQL、把 SQL Server 换成别的，这段代码要改吗？**」
- 要改 → Infrastructure
- 不用改但属于业务流程 → Application
- 属于业务规则本身 → Domain
- 纯粹是 HTTP 的事 → Api
