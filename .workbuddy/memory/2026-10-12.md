## 登录验证思路讲解（20:31，仅讨论不落码）

- 用户明确要求「不写代码」，只讲实现思路，自己动手写。
- 主线五步：接收专用 DTO → 准入防护（限流 + 失败锁定）→ 按用户名查用户 → 校验密码哈希 → 签发 Access + Refresh Token。
- 关键取舍建议：
  - 密码哈希用内置 `PasswordHasher<T>`（PBKDF2-HMAC-SHA256，自带随机盐）或 BCrypt.Net-Next，**禁用 MD5/SHA256/明文**；哈希列宽给 nvarchar(200) 以上。
  - 用户不存在与密码错误 **返回同一文案**，防用户名枚举；用户不存在时也跑一次假哈希校验，避免时序攻击泄露。
  - JWT payload 是 Base64 **不是加密**：放 sub / 用户名 / 角色 / 租户与工厂范围，不放敏感信息。校验一律交给 JwtBearer 中间件 + `[Authorize]`，不手写解析。
- **ERP 特有坑（已提示）**：
  - 登录接口必须显式 `[AllowAnonymous]`，否则全局 fallback policy 会造成「登录需要先登录」死循环。
  - 多工厂/多租户下唯一索引应为 `(TenantId, UserName)` 复合。
  - 账号锁定需自动解锁或管理员解锁，否则可被恶意锁死（拒绝服务）。
  - 改密码后旧 Token 仍有效（JWT 无状态）——需 `SecurityStamp` 校验或接受该窗口。
  - 建议落登录审计日志表（成功/失败/IP/时间）。
